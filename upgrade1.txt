PART 2: MVP SCOPE — WHAT SHIPS
--------------------------------------------------------------------------------

MVP Definition: A student can (1) take a structured lesson with real exercises,
(2) have an AI text conversation, (3) review cards with spaced repetition,
(4) see their progress/streak, and (5) a tutor can run a live session with
polling. Voice and gamification are POST-MVP.

MVP In Scope:
  ├── Structured class with working exercises and real scoring
  ├── AI text conversation (Gemini text API, not voice)
  ├── SRS flashcard system with server persistence
  ├── Confidence meter / micro-polling in live sessions
  ├── Progress sync + streak display
  ├── Lesson generation endpoint (fill the 49 empty combos)
  └── Clean, tested, deployable code

MVP Out of Scope (deferred):
  ├── Voice conversation (Gemini Live / LiveKit / WebRTC — pick one later)
  ├── Peer challenges / leaderboards
  ├── Pronunciation heatmaps / STT scoring
  ├── Full teacher dashboard with analytics
  ├── Drag-drop interactive slates (fill-blank first)
  └── Email/password auth (keep JWT + display name)

PHASE 4: SPACED REPETITION (Days 21-28)
Make Mode B's SRS actually spaced.
═══════════════════════════════════════════════════════════════════════════════

4.1  SRS database schema
     - New table in server/db.js:
       CREATE TABLE review_cards (
         id TEXT PRIMARY KEY,
         user_id TEXT NOT NULL,
         card_data TEXT NOT NULL,        -- JSON: { front, back, source }
         ease_factor REAL DEFAULT 2.5,
         interval_days INTEGER DEFAULT 0,
         repetitions INTEGER DEFAULT 0,
         next_review_at INTEGER NOT NULL,
         last_reviewed_at INTEGER,
         FOREIGN KEY(user_id) REFERENCES users(id)
       )
     - Index on (user_id, next_review_at)

4.2  SM-2 algorithm
     - utils/srs.ts: calculateNextReview(card, quality) → updated card
     - quality 0-5 (Again/Hard/Good/Easy)
     - Standard SM-2 intervals: 1, 3, 7, 14, 30, 60, 120... days
     - Handle "Again" → reset interval to 0, requeue today

4.3  Server API
     - GET  /api/users/:id/srs/due        → cards due today
     - POST /api/users/:id/srs/:cardId    → submit review result
     - POST /api/users/:id/srs/bulk       → import cards from session
     - All behind requireAuth

4.4  Card feed from sessions
     - On LessonComplete → extract vocabulary + corrections → import to SRS
     - On review-history study → import flagged cards to SRS
     - On AI chat corrections → import to SRS (Phase 1 output)

4.5  Redesign FlashcardReview

     - Add quality rating buttons (Again/Hard/Good/Easy)
     - Show next-review date after rating
     - Persist after each card review

4.6  Due-card dashboard
     - Show "X cards due" badge on ModeSelector

     Deliverable: Cards scheduled by SM-2, due queue, persistent across devices.
